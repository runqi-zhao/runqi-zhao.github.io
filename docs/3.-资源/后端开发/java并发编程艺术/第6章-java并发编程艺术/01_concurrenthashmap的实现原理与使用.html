concurrentHashMap介绍

锁分段技术

HashTable效率底下的原因是一次只能一个线程访问，意味着另外一个线程的put当前线程不使用的数据也会进行阻塞。

假设我们将每个数据进行“分离”，相当于一个线程进行put操作时仅仅锁住当前的数据，其他线程put其他数据的时候不受影响，这就是锁分段技术，可以提高并发访问率。

为了保证这种结构，ConcurrentHashMap在进行设计时，有了以下结构：

ConcurrentHashMap的类图

ConcurrentHashMap的结构图

如图，ConcurrentHashMap是由Segment数组结构和HashEntry数组结构组成。

Segment是一种可重入锁（ReentrantLock），在ConcurrentHashMap扮演着锁的角色；Segment的结构和HashMap类似，是一种数组和链表结构.

HashEntry用于存储键值对数据，每个HashEntry是一个链表结构的元素，每个Segment守护着一个HashEntry数组里的元素，当对HashEntry数组的数据进行修改时，必须首先获得与它对应的Segment锁。

一个ConcurrentHashMap里包含一个Segment数组，一个Segment数组里面包含一个HashEntry数组。

get操作的高效之处在于整个get过程不需要加锁，除非读到的值是空才会加锁重读。get方法使用的共享变量都是volatile类型，如用于统计当前Segement大小的count字段和用于存储值的HashEntry的value。

定义成volatile类型，可以保证可见性，能够让多个线程同时进行读，并且不会读到过期值，但是只能由一个线程写（如果可以被多个线程写，那么这个值就是不依赖原值）。

保证不会读到过期值的原因是：java内存模型之中存在**happens-before**原则，对volatile字段的写入操作先于读操作，即使读写线程同时到达，也是限制性写线程，在执行读线程。

在get操作里只需要读不需要写共享变量count和value，所以可以不用加锁。

put

put方法首先定位到Segment，然后在Segment里进行插入操作。插入操作需要经历两个步骤：

  1. 判断是否需要对Segment里的HashEntry数组进行扩容；
  2. 定位添加元素的位置，然后将其放在HashEntry数组里。

是否需要扩容

在插入元素前会先判断Segment里的HashEntry数组是否超过容量（threshold），如果超过阈值，则对数组进行扩容。

在进行扩容时，比HashMap合理，避免了无效扩容（因为HashMap是在插入元素之后，有可能时最后一次，下次不再使用还进行了扩容）。

如何扩容

在扩容的时候，首先会创建一个容量是原来容量两倍的数组，然后将原数组里的元素进行再散列后插入到新的数组里。为了高效，ConcurrentHashMap不会对整个容器进行扩容，而只对某个segment进行扩容。

size

如果要统计整个ConcurrentHashMap里元素的大小，就必须统计所有Segment里元素的大小后求和。

Segment里的全局变量count是一个volatile变量，多线程场景下，可能存在变化，因此，为了统计准确，产生了以下几种方法：

  1. 在统计size的时候把所有Segment的put、remove和clean方法全部锁住，但是这种做法显然非常低效；
  2. 先尝试2次通过不锁住Segment的方式来统计各个Segment大小，如果统计的过程中，容器的count发生了变化，则再采用加锁的方式来统计所有Segment的大小。

如何判断在统计时容器发生了变化呢？

使用modCount变量。使用modCount变量，在put、remove和clean方法里操作元素前都会将变量modCount进行加1，那么在统计size前后比较modCount是否发生变化，从而得知容器的大小是否发生变化。
