什么是AI Agent/Workflow

没有一个统一的定义：

  • Agent定义为完全自主的系统，这些系统可以在较长时间内独立运行，使用各种工具完成复杂任务。
  • 描述一种遵循定义工作流的规范实现。

统称为智能系统

workflow vs. Agent

  • Workflow：通过预定义的代码路径来编排大模型和工具；
  • Agent：大模型动态决定自己的流程及使用什么工具，自主控制如何完成任务

何时使用/不使用Agent & Workflow

寻找尽量可能简单的方案，只有在必要是才增加复杂性。

  • 如果没有必要，不要试图构建Agent/Workflow。
  • 存在延迟，更高的成本，在处理任务的时候需要权衡利弊。

如果确实要解决复杂场景的问题，

  • Workflow为明确定的任务提供了可预测性和一致性；
  • Agent则在需要大规模灵活性和模型驱动的决策时是一个更好的选择。

大模型本身加上RAG、in-context examples等技术通常可以解决问题了。

何时以及如何使用框架

许多框架可以简化 Agent/Workflow 的实现，包括：

  • LangGraph from LangChain;
  • Amazon Bedrock’s AI Agent framework;
  • Rivet, a drag and drop GUI LLM workflow builder; and
  • Vellum, another GUI tool for building and testing complex workflows.

这些框架通过简化标准的底层任务（如调用LLM、定义和解析工具以及链接调用）是用户更加容易入门。但是他们通常会创建额外的抽象层，这样会使底层的提示和响应变得难以调试，增加了不必要的复杂性。

建议：

  • 首选直接使用LLM API
  • 如果确实要用框架，要确保理解这些框架的底层代码。

基础多 LLM 工作流

本笔记本展示三种简单的多大语言模型（LLM）工作流。它们以成本或延迟方面的代价，换取潜在的任务表现提升：

  1. 提示词链（Prompt-Chaining）：将任务分解为顺序执行的子任务，每一步都基于前面的结果继续处理。
  2. 并行化（Parallelization）：将相互独立的子任务分配给多个 LLM，并发处理。
  3. 路由（Routing）：根据输入特征，动态选择专门的 LLM 处理路径。

2 Workflow & Agent 的基础构建模块

增强型大模型（augmented LLM）

Agent/Workflow的基本构建模块是一个增强型大预言模型，

模型具有检索、工具和记忆等增强功能。模型可以主动使用这些功能。

功能选型建议

  1. 不是所有功能都需要用上，而应该根据你的实际需求，只保留最必要的部分；
  2. 尽量使用那些文档完善的组件，否则就是给自己挖坑。

小结

基于增强大模型，我们就可以构建出各种AI Workflow &Agent。

提示链（prompt chaining）

提示链将任务分解为一系列顺序的子任务，

  • 每个 LLM call 处理前一个 LLM call 的输出；
  • 可以在中间任何步骤添加检查点（图中的 “Gate”），以确保处理过程仍在正轨上。
使用场景

能够干净的将任务分解成固定子任务的场景。

相比于一整个大任务，查节后的每个LLM call都是一个准确率更高、延迟更低、更容易完成的任务。

场景举例

生成营销文案

生成营销文案，然后将其翻译成不同的语言。

按大纲编写文档

首先编写文档大纲，确保大纲符合某些标准，然后根据大纲编写文档。

路由（Routing）

任务转发，转发到专门的后续任务

  • 将任务的关注点进行拆解，从而针对每个具体任内务设计和调整提示词。
  • 否则，（all-in-one）提示词不仅很长，而且针对任何一种任务的提示词优化都可能会导致其他任务的性能下降。

适用场景

  • 适用于存在不同类别的复杂任务，而且这些类别分开处理时，都能得到更好的效果。
  • 前提是能够准确分类，至于是使用大模型分类，还是使用传统模型/算法分类，关系不大。

并行化

对输出进行聚合处理

  1. 分段（Sectioning）：类似 MapReduce，将任务分解为独立的子任务并行运行，最后对输出进行聚合。
  2. 投票（Voting）：相同的任务并行执行多次，以获得多样化的输出。
适用场景

分为两类：

  1. 并行化可以提高任务的最终完成速度，
  2. 需要多种视角或尝试，对所有结果进行对比，取最好的结果。

Agent设计三原则

  1. Agent 设计的简洁性。
  2. Agent 工作过程的透明性，例如能明确显示 Agent 的规划和步骤。
  3. 通过完善的文档和测试，精心设计 Agent 与计算机之间的接口（agent-computer interfaces, ACI）。

极力减少抽象层，尽量使用基本组件

总结

Agent以及Workflow都是一种模式，不是规范

能衡量系统的性能，然后不断对实现进行改进和迭代。

不是构建最复杂的系统，而是构建符合你需求的系统。

只有在性能有明显改善时，才应该考虑增加复杂性。

智能体时能够独立代表您完成任务的系统。

智能体的设计基础

三个核心组件构成：

  1. 模型：驱动智能体推理和决策的大型语言模型（LLM）。
  2. 工具：智能体可以用来执行操作的外部函数或API。
  3. 指令：定义智能体行为的明确指定方针和防护边界。

选择模型

原则如下：

  1. 建立评估以确定性能基准。
  2. 优先使用最佳模型以达到您的准确性目标。
  3. 优化成本和延迟，在可能的情况下用较小的模型替换较大的模型。

定义工具

智能体需要一下三类工具：

类型描述例子
信息检索工具使智能体能够获取执行工作流程所需的上下文和信息
执行工具使智能体能够与系统交互以执行操作，例如向数据库添加新信息、更新记录或发送消息
编排工具智能体本身可以作为其他智能体的⼯具

编排

编排模式分为两大类：

  1. 单智能体系统：由单一模型适配适当的工具和钟灵，在循环中执行工作流程。
  2. 多智能体系统：工作流程执行分布在多个协调的智能体之间。
