# 知识库使用指南

返回 [[首页]]

## 一条信息如何流动

1. **先捕获**：来不及判断时放进 [[-1. 捕获/README|收件箱]]。
2. **再澄清**：判断它是项目、领域、资源还是输出。
3. **建立连接**：每篇长期保留的知识至少连接一个 MOC；有明确关系时再连接具体笔记。
4. **形成输出**：能解释、比较或解决问题时，转化为 [[5. 表达/README|文章或分享]]。
5. **定期归档**：不再活跃但仍有价值的内容放入 `4. 存档`。

## 文件夹职责

- `-1. 捕获`：尚未处理的信息；目标是定期清空。
- `1. 项目`：有明确结果与期限；没有活跃项目时可以为空。
- `2. 领域`：长期责任，如职业发展、家庭、健康。
- `3. 资源`：可复用的知识与资料。
- `4. 存档`：不活跃内容，只保留，不继续维护。
- `5. 表达`：博客、分享、总结等可交付成果。

## 属性规范（保持最少）

| 属性 | 用途 | 常用值 |
|---|---|---|
| `type` | 笔记类型 | `capture`、`knowledge`、`project`、`area`、`output`、`moc`、`dashboard` |
| `status` | 当前状态 | `inbox`、`active`、`paused`、`done`、`archived` |
| `moc` | 所属知识导航，可多选 | `[[后端开发 MOC]]` |
| `area` | 服务的长期领域 | `[[职业发展]]` |
| `project` | 当前关联项目 | 项目链接；没有则留空 |
| `source` | 原始来源 | URL、书籍或课程 |

## 标签规范

标签只表示**跨主题的工作流状态**，不再用来复制文件夹结构：

- 可用：`#待整理`、`#待验证`、`#待输出`
- 不建议：`#Java/MySQL/索引` 这类主题层级；主题关系改用 MOC 和链接。
- 旧标签暂不批量删除，避免误伤代码片段中的 `#`。

## 命名规范

- 技术名保留官方英文，其余使用中文，例如 `Redis 持久化机制.md`。
- 知识笔记标题尽量写成“问题”或“结论”，避免 `Untitled`、`总结2`。
- 课程笔记可以保留编号，但必须通过所属 MOC 找到。
- `README` 只承担文件夹说明；知识导航统一使用 `主题 MOC`。

## 每周 15 分钟维护

- 清空或缩小收件箱；
- 为本周新知识补 `moc` 和 1～2 个具体链接；
- 检查 [[待整理清单]]；
- 检查 [[知识保鲜看板]] 的「已过期」前 10 条，续期或归档；
- 从本周笔记中选择一个主题形成输出；
- 将完成或暂停的项目调整状态。

## 新增：抓取 / 期限 / 关联 / 被引用

### 1. 抓取：从「看到」到「进库」不超过 10 秒

| 来源 | 动作 |
|---|---|
| 网页 / 公众号 | 浏览器装 Obsidian Web Clipper，模板选 `templates/剪藏-网页.md`，剪到 `-1. 捕获` |
| 抖音 / B站 / YouTube | 命令面板 → `QuickAdd: 剪藏视频（抖音/B站）`，粘贴链接，套 `templates/剪藏-视频.md` |
| PDF / 电子书 | 命令面板 → `QuickAdd: 剪藏网页` 或直接复制 PDF 进笔记目录，用 PDF++ 划词标注（标注自动带回链） |
| 微信碎片、临时想法 | 命令面板 → `QuickAdd: 快速捕获（碎片想法）`，直接追加到 `-1. 捕获/收件箱.md` |

QuickAdd 的四条命令已经预置好，文件名、目录、frontmatter 都会自动填。手机上用 Obsidian App + Remotely Save 同步到同一个收件箱。

### 2. 期限：每条知识都有保质期

frontmatter 新增三个字段：

```yaml
kind: tech            # tech 技术/版本敏感 90 天 | method 方法论/工具 365 天 | ever 原理概念 不过期
last_reviewed: 2026-10-28
review_after: 2027-01-26   # = last_reviewed + 有效期，脚本算
```

- 看板：[[知识保鲜看板]]（已过期 / 30 天内到期 / 未归类 / 健康度）
- 复核一篇后：把 `last_reviewed` 改成今天 → 跑 `python scripts/kb_review.py --apply`
- 只续一篇：`python scripts/kb_review.py --apply --renew "3. 资源/xxx.md"`
- 现有 431 篇已按目录批量归类（3. 资源 = tech，其余 = method，MOC/存档 = ever）。技术类里其实很多是「原理」，看到就把它改成 `ever`，一个月后看板会越来越准。

### 3. 关联：MOC + 双链 + 语义

- 向上：每篇挂一个 `moc`（[[后端开发 MOC]] 等），看板 [[知识关联体检]] 会列出没挂的；
- 横向：正文里写「和 [[已有笔记]] 的关系是……」，不写只有链接没有关系的话；
- 语义：Smart Connections 插件在右侧栏按向量推荐相关笔记，点一下就能拖进正文变成链接；
- 每周跑一次 [[知识关联体检]]，先修「孤岛笔记」。

### 4. 被搜索和 AI 引用

站点：Quartz 静态站 → https://runqi-zhao.github.io （GitHub Pages 免费托管，仓库 `runqi-zhao/runqi-zhao.github.io`，Pages 源 `main:/docs`）

- 发布一条命令：`python scripts/publish_site.py --push`（同步 → 构建 → 生成 llms → 推送），1～2 分钟后线上更新；
- 只改笔记想先本地看：`python scripts/publish_site.py`，产物在 `E:/code/quartz-kb/docs`；
- 凭据已存在 Windows 凭据管理器（GCM），`git push` 不需要再填 token；
- 给 AI 的入口：站点根目录自动生成 `llms.txt`（全站目录 + 摘要）和 `llms-full.txt`（全文），ChatGPT / Perplexity / Claude 可以直接读；
- 给搜索引擎的入口：`sitemap.xml`、RSS、语义化 HTML、每篇独立 URL；
- 本地 AI（Hermes / OpenCode / Claude Code）直接读 vault 文件，不需要额外配置。
