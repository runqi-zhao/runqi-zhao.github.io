## Docker的诞生

本来的PaaS服务不具备镜像打包的功能，等于想要部署在服务器上面，需要先根据虚拟机将环境适配好，然后再运行，对于开发与意识增加成本的。

因此，出现Docker镜像服务概念，等于说提供一个镜像，当你使用这个镜像的时候，里面已经配置好了对应的环境。

此项技术的出现，直接导致使用市场的火爆，都拿那么点钱，为啥不选个省事的方法？

## Docker的发展

这个发展主要就是Docker火爆之后，使用了容器编排的概念。

“编排”（Orchestration）在云计算行业里不算是新词汇，它主要是指用户如何通过某些工具或者配置来完成一组虚拟机以及关联资源的定义、配置、创建、删除等工作，然后由云计算平台按照这些指定的逻辑来完成的过程。

Docker收购了Fig，命名为Compose，Fig会把这些容器内容的定义交给Docker API，API按照访问逻辑依次创建，一些容器都将会进行启动。而容器 A 与 B 之间的关联关系，也会交给 Docker 的 Link 功能通过写入 hosts 文件的方式进行配置。更重要的是，你还可以在 Fig 的配置文件里定义各种容器的副本个数等编排参数，再加上 Swarm 的集群管理能力，一个活脱脱的 PaaS 呼之欲出。

Fig 项目被收购后改名为 Compose，它成了 Docker 公司到目前为止第二大受欢迎的项目，一直到今天也依然被很多人使用。

## Kubernetes的崛起

Docker火爆之后，Docker公司专注于商业化。导致开发者不能很好地沟通。

此时，k8s出现，直接进行开源，然后都让用户自行决定，暴露接口，根据自己想要的功能实现对应的插件。k8s取得了成功。
