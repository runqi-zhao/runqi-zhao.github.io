## 并发编程模型的两个关键问题

在并发编程中，需要处理两个关键问题：

1. 线程之间如何通信。
2. 线程之间如何同步。

这里的线程是指并发执行的活动实体。

通信是指线程之间以何种机制来交换信息。在命令式编程中，线程之间的通信机制有两种：共享内存和消息传递。

1. 在共享内存的并发模型里，线程之间共享程序的公共状态，通过写-读内存中的公共状态进行隐式通信。在消息传递的并发模型里，线程之间没有公共状态，线程之间必须通过发送消息来显式进行通信。
2. 同步是指程序中用于控制不同线程间操作发生相对顺序的机制。在共享内存并发模型里，同步是显式进行的。程序员必须显式指定某个方法或某段代码需要在线程之间互斥执行。在消息传递的并发模型里，由于消息的发送必须在消息的接收之前，因此同步是隐式进行的。

Java的并发采用的是共享内存模型，Java线程之间的通信总是隐式进行，整个通信过程对程序员完全透明。如果编写多线程程序的Java程序员不理解隐式进行的线程之间通信的工作机制，很可能会遇到各种奇怪的内存可见性问题。

## Java内存模型的抽象结构

Java中，堆结构如下图

![java堆结构](https://img-1312072469.cos.ap-nanjing.myqcloud.com/java%E5%A0%86%E7%BB%93%E6%9E%84.jpg)

其中，共享指的是线程之间共享。

<font color="red">java线程之间通信是由Java内存模型（JMM）控制。JMM决定一个线程对共享变量的写入何时对另一个线程可见。</font>

JMM定义了线程和主存之间的抽象关系：

- 线程之间的共享变量存储在主内存之中
- 每个线程存在本地内存（抽象概念，并不真实存在）
  - 本地内存包括
    - 缓存
    - 写缓冲区
    - 寄存器
    - 其他硬件
    - 编译器优化
- 本地内存保存共享内存副本

![](https://img-1312072469.cos.ap-nanjing.myqcloud.com/20230425104515.png)

<center>线程之间的通信</center>

线程之间如何进行通信？

1. 线程A把本地内存中的变量通过共享变量刷新到主内存中去
2. 线程B从主内存中去读取线程A之前更新过的共享变量

![image-20221204212230918](https://img-1312072469.cos.ap-nanjing.myqcloud.com/image-20221204212230918.png)

<center>线程之间的通信</center>

从总体来看，JMM通过控制主内存于每个线程之间的交互，来控制内存的可见性。

如上图所示，本地内存A和本地内存B由主内存中共享变量x的副本。假设初始时，这3个内存中的x值都为0。线程A在执行时，把更新后的x值（假设值为1）临时存放在自己的本地内存A中。当线程A和线程B需要通信时，线程A首先会把自己本地内存中修改后的x值刷新到主内存中，此时主内存中的x值变为了1。随后，线程B到主内存中去读取线程A更新后的x值，此时线程B的本地内存的x值也变为了1。

从整体来看，<font color="red">这两个步骤实质上是线程A在向线程B发送消息，而且这个通信过程必须要经过主内存。</font>JMM通过控制主内存与每个线程的本地内存之间的交互，来为Java程序员提供内存可见性保证。

## 从源代码到指令序列的重排列

![从源代码到最终执行的指令序列的示意图](https://img-1312072469.cos.ap-nanjing.myqcloud.com/%E4%BB%8E%E6%BA%90%E4%BB%A3%E7%A0%81%E5%88%B0%E6%9C%80%E7%BB%88%E6%89%A7%E8%A1%8C%E7%9A%84%E6%8C%87%E4%BB%A4%E5%BA%8F%E5%88%97%E7%9A%84%E7%A4%BA%E6%84%8F%E5%9B%BE.jpg)

为了提高性能，编译器和处理器会对指令进行重排序：

1. 编译器优化的重排序

   重新安排语句执行顺序，在不改变语义的前提下

2. 指令级并发的重排序

   将多条语句叠加执行。不存在数据依赖性时，处理器可以改变语句对应机器指令的执行顺序。

3. 内存的重排序

   处理器使用缓存于读/写缓冲区，是的加载存储操作看上去在乱序执行

2 3属于处理器重排序 1 属于编译器重排序

<font color="red" size="8">导致问题：内存可见性问题</font>

解决办法

1. 编译器：JMM编译器重排序规则会**<font color="red">禁止特定类型</font>**的编译器重排序
2. 处理器：JMM的处理器重排序要求规则要求Java编译器在生成对应的指令序列之前，插入特定类型的**<font color="red">内存屏障</font>**指令，通过内存屏障指令**<font color="red">禁止类特定类型</font>**的处理器重排序。

### 并发编程模型的分类

现代处理器使用写缓冲区临时保存向内存写入的数据

好处

1. 写缓冲区可以流水线执行，避免处理器停顿带来的延迟；
2. 批处理方式写入写缓冲区，合并写缓冲区对于廷议内存地址的多次写，减少对总线的占用。

坏处：

1. <font color="red">每个处理器的写缓冲区只对本处理器可见</font>；会产生脏读
2. 可见性如何保证？

## happens-before简介

目前，java使用JSR-133内存模型，在JSR-133中，使用happens-before的概念来阐述操作之间的内存可见性。即，在JMM中，如果一个操作执行的结果对另一个操作可见，那么这两个操作之间必须存在happens-before关系。其中的两个操作的是否为一个线程任意。

happens-before的规则：

1. 程序顺序规则：一个线程中的每个操作，happens-before与该线程中的任意后续操作。

   两个操作具有happens-before关系，并不意味着前一个操作必须要在后一个操作之前执行！仅仅要求前一个操作（执行结果）对后一个操作可见，且一个操作按顺序排在第二个操作之前。

2. 监视器锁规则：对一个锁的解锁，happens-before于随后对这个锁的加锁。

3. volatile变量规则：对一个volatile域的写，happens-before于任意后续对这个volatile域的读。

4. 传递性：A happens-before B, B happpens-before C -> A happens before C

![](https://img-1312072469.cos.ap-nanjing.myqcloud.com/image-20221207100407303.png)

<center>happens-before与JMM的关系</center>

- **<font color="red">一个happens-before对应于一个或多个编译器和处理器重排序规则。</font>**
- 对于java程序员来说，happens-before避免了为了理解JMM提供的内存可见性保证而去学习复杂的重排序规则以及这些规则的具体实现方法
