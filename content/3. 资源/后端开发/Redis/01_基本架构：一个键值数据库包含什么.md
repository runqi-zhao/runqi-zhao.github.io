这一节主要就是引出一些Redis能够解决的问题以及基本架构

## 存储方式

使用K-V进行存储。

好处：能够节省存储空间，在基于索引查找的时候，能够通过key快速的找到对应的Value。Value的数据结构多样：可以是String类型，哈希表类型，列表类型、集合类型。**这是一个面试常问的知识点，因此要好好总结**。

## 可以对数据进行什么操作

- PUT：新写入或更新一个key-value对。
- GET：根据一个key读取相应的value值。
- DELETE：根据一个key删除整个key-value对。

有些键值 数据库的新写/更新操作叫SET。

即根据一段 key 的范围返回相应的 value 值。因此，PUT/GET/DELETE/SCAN 是一个键值数据库的基本操作集合。

知道这些如何进行操作，对应的键值对应该保存在内存还是外存里面？

答案：根据实际场景进行设计，一般情况下，Redis是将对应的数据存储在对应的内存之中 ，并且使用 对应的AOF模式备份。

## 采用什么访问模式

访问模式通常有两种：

1. 通过函数库调用的方式供外部应用使用。
2. 通过网络框架以Socket通信的形式对外提供键值对操作。

Redis 则是通过网络框架访问。后面我还会给你介绍 Redis 现有的客户端和通信协议。

会存在什么问题 ：

在编写对应键值数据库所使用的对应的包，并按照对应的协议进行解析之后 ，用户写入一个键值对，开始对应的流程，但是此时存在的问题：简单来说，就是网络连接的处理、网络请求的解析，以及数据存取的处理，是用一个线程、多个线程，还是多个进程来交互处理呢？该如何进行设计和取舍呢？我们一般把这个问题称为 I/O 模型设计。不同的 I/O 模型对键值数据库的性能和可扩展性会有不同的影响。

这里的话Redis采用单线程，但是在使用“单线程 ”的情况下又能保证高性能，这是怎么进行实现的。**这是一个重点，后面需要重点进行讲解**。

## 如何定位 键值对的位置？

一般情况下，Redis使用索引进行定位。

Redis索引在进行创建的时候使用哈希表作为索引。原因：Redis其键值数据基本都是保存在内存中的，而内存的高性能随机访问特性可以很好地与哈希表 O(1) 的操作复杂度相匹配。

## 不同操作的具体逻辑是怎么样的？

四个操作都要过索引层和存储层两遍：哈希表负责定位，内存负责存值。

- PUT：在哈希索引里找到或新建 key，把 value 写进内存，同时把命令追加到 AOF 日志。
- GET：用 key 查哈希表拿到 value 的位置，直接读内存。
- DELETE：从哈希表摘掉 key，释放对应 value，并记一条删除日志。
- SCAN：用游标在哈希表上分批遍历，每次返回一批 key，不保证顺序。
