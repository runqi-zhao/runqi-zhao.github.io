看事物要看全貌，不能只看其中的一部分。

咱们从一个简单的SELECT语句说起，说明SQL语句是如何运行的：

```shell
mysql> select * from T where ID=10；
```

下面给出的是MySQL的基本架构示意图，从中可以清楚地看到SQL语句在MySQL的各个功能模块的执行过程。

![img](https://img-1312072469.cos.ap-nanjing.myqcloud.com/0d2070e8f84c4801adbfa03bda1f98d9.png)

大体来说，MySQL可以分为Server层和存储引擎层两个部分。

- Server层包括连接器、查询缓存、分析器、优化器、执行器等，涵盖MySQL的大多数核心服务功能，以及所有的内置函数（如日期、时间、数字和贾母函数），所有跨存储引擎的功能都在这一层进行实现，比如存储过程、触发器、视图等。
- 存储引擎曾负责数据的存储和提取。其架构模式是插件式的，支持InnoDB、MyISAM、Memory 等多个存储引擎。现在最常用的存储引擎是 InnoDB，它从 MySQL 5.5.5 版本开始成为了默认存储引擎。

不同的存储引擎公用一个Server层，也就是从连接器到执行器的部分。

## 连接器

1. 首先需要连接到这个数据库上面，这个时候使用到的就是连接器。连机器负责跟客户段建立连接、获取权限、维持和管理连接。连接命令一般是这么写的：

```shell
mysql -h$ip -P$port -u$user -p
```

默认链接最长时间是8小时。

但是全部使用长连接后，你可能会发现，有些时候 MySQL 占用内存涨得特别快，这是因为 MySQL 在执行过程中临时使用的内存是管理在连接对象里面的。这些资源会在连接断开的时候才释放。所以如果长连接累积下来，可能导致内存占用太大，被系统强行杀掉（OOM），从现象看就是 MySQL 异常重启了。怎么解决这个问题呢？

你可以考虑以下两种方案。

1. 定期断开长连接。使用一段时间，或者程序里面判断执行过一个占用内存的大查询后，断开连接，之后要查询再重连。
2. 如果你用的是 MySQL 5.7 或更新版本，可以在每次执行一个比较大的操作后，通过执行 mysql_reset_connection 来重新初始化连接资源。这个过程不需要重连和重新做权限验证，但是会将连接恢复到刚刚创建完时的状态。

## 查询缓存

连接建立完成之后，下面就来到第二部，查询缓存。

MySQL拿到之后，就会查看缓存，如果之前运行过，那么直接击中缓存，拿到里面对应的缓存，不用再继续执行，如果没有拿到对应的缓存，那么则需要执行下一步的语法分析。

**但是大多数情况下我会建议你不要使用查询缓存，为什么呢？一般情况下我们都要对表进行更新，那么查询缓存的存在将会加重运行时的负担。**

## 分析器

如果查询缓存没有命中，那么接下来就会来到分析器，执行语句。

首先分析器会做“词法分析”，输入是由多个字符除按和空格组成的一条SQL语句，MySQL需要识别出里面的字符除按分别是什么， 代表什么。

MySQL 从你输入的"select"这个关键字识别出来，这是一个查询语句。它也要把字符串“T”识别成“表名 T”，把字符串“ID”识别成“列 ID”。

做完这些表之后，需要做的就是“语法分析”

## 复习

这即将主要就是讲了MySQL的运行机制：

在进行执行的时候，需要经过下面几个步骤：

1. 连接器
2. 分析器
3. 优化器
4. 执行器
5. 存储引擎

首先客户端在命令行界面输入对应的连接语句：

```
mysql -h$ip -P$port -u$user -p
```

这个过程其实是通过TCP进行连接，确保其中对应的连接是可靠的

然后再MySQL对应的配置文件中，有对应的空闲时长，当到达对应的空闲市场之后，会自动断开对应的连接。当然，也有最大连接数，我记得我上本科的时候很喜欢看这个文件。，

OK，指导对应的连接器之后，下面来到对应的分析器，分析器顾名思义，就是分析词法以及语法，在使用分析器的时候，会有一个对应的查询缓存。但是不建议使用对应的查询缓存，理由就是在使用查询缓存的时候需要保证对应的内容是完全一致的，这将会导致对应的内容一段变换，缓存将不再可用，这个时候将会增加查找查询缓存的时间。

然后发分析器在进行分析的时候，主要分为对SQL语句的此法分析以及对应的语法分析，一般这个按照对应的规则和语法来，都是没有问题的。

然后接下来就到了对应的优化器，优化器就是执行生成计算，如果说有对应的索引，选择出对应的索引，没有对应的索引则判断是不是有其他可以加速的内容，都没有则生成对应的语法树，然后进行执行。

最后来到对应的执行器，在执行器进行执行的时候，首先判断是否有对应的权限，如果说又对那个的权限，继续执行，打开表的时候，判断对应的引擎接口，以InnoDB为例，对应的执行引擎是这样的：

1. 调用 InnoDB 引擎接口取这个表的第一行，判断 ID 值是不是 10，如果不是则跳过，如果是则将这行存在结果集中；
2. 调用引擎接口取“下一行”，重复相同的判断逻辑，直到取到这个表的最后一行。
3. 执行器将上述遍历过程中所有满足条件的行组成的记录集作为结果集返回给客户端。

相当于现在咱们有一个对应的树结构，按照这个树结构进行执行，将会得到对应的结果。
