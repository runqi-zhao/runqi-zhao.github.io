为社么需要加锁？

多个线程并发访问时，可能会出现脏读以及幻读，加上锁的目的就是保证数据可以正确写入与读取。

MySQL中锁大致可以分为全局锁、表级锁和行锁三类。

## 全局锁

顾名思义，对整个数据库示例加锁。MySQL 提供了一个加全局读锁的方法，命令是 Flush tables with read lock (FTWRL)。

全局锁的使用场景为全库逻辑的备份。

既然要全库制度，为什么不使用 set global readonly=true的方式呢？

两个原因：

1. 有些系统中，readonly的值会被用来做其他逻辑，比如用老判断一个库时主库还是备库。因此，修改global变量的方式影响面更大。
2. 异常处理机制上面有差异。如果执行FTWRL命令之后由于客户端发生异常断开，那么MySQL慧自动释放这个全局锁，正好个库回到可以正常更新的状态。而将整个库设置为readonly之后，如果客户端你发生异常，则数据库就会一致保持readonlu状态，这样回导致整个库长时间处于不可写抓昂太，风险高。

## 表级锁

### 表锁

```sql
lock tables ...read/write
```

### 元数据锁

MDL 不需要显式使用，在访问一个表的时候会被自动加上。MDL 的作用是，保证读写的正确性。

MDL锁在添加字段进行使用的时候，需要特别注意，在进行表字段添加以及更新操作时，很容易造成阻塞操作。

**如何安全的给表添加字段？**

1. 解决长事务，长事务不提交，就会一直占着MDL锁。因此MySQL的information_schema 库的 innodb_trx 表中可以查到当前执行中的事务。如果在做DDL变更的表刚好有长事务在执行，要先考虑暂停DDL，或者kill掉这个长事务。
2. 但是对于更新量大的表，使用kill明显不现实，因此比较理想的机制是，在alter table语句里面设置等待时间，如果这个指定的等待时间里面里面执行DDL最好，如果说没有，选放弃，执行后面的语句。
