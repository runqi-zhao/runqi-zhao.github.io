下面是使用循环链表进行实现的。

```java
class Solution {

    class ListNode//链表节点
    {
        int val;
        public ListNode(int value) {
            this.val=value;
        }
        ListNode next;
    }

     public int iceBreakingGame(int n, int m) {
        if (m == 1) {
            return n - 1;
        }
        ListNode head = new ListNode(0);
        //创建对应的循环链表
        ListNode node = head;
        for (int i = 1; i < n; i++) {
            node.next = new ListNode(i);
            node = node.next;
        }
        node.next = head;
        //创建完成

        //下面找到对应的数
        int index = 0;
        //现在这里从1开始计数，因此我们要删除的节点是m-1。
        //因此要再m-2的时进行标记，删除后面的节点。
        while (head.next != head) {
            if (index == m - 2) {
                //删除对应的节点
                head.next = head.next.next;
                index = 0;
            } else {
                index++;
            }
            head = head.next;
        }
        //删除完毕，最后会剩下一个节点，返回
        return head.val;
    }
}
```

上面使用链表直接模拟游戏过程会造成非常严重非常严重的超时，n个人，数到第m个杀死。因为n如果非常大远远大于m，那么将进行很多次转圈圈。

![img](https://img-1312072469.cos.ap-nanjing.myqcloud.com/1620465222-mhrekj-file_1620465222674)

所以我们可以使用求余的方法判断等价最低的枚举次数，然后进行删除即可，因此，我们仍然使用循环链表，但是对应删除的m，我们需要使用while循环集以上只需要添加一个记录长度每次秋雨算圈数即可：

```java
int len=n;
while (head.next!=head) {
  if(index==(m-2)%len){
    head.next=head.next.next;
    index=0;
    len--;
  }
  else {
    index++;
  }
  head=head.next;
}

```

但是，这个题目真的需要链表吗，答案是否定的 。

假设当前长度为n，数到第m个(通过上面分析可以求余让这个有效的m不大于n)删除，在index位置删除。那么删除后剩下的就是n-1长度，index位置就是表示第一个计数的位置，我们可以通过求余得知走下一个删除需要多少步，那么下个位置怎么确定呢？

![删除3号下标](https://img-1312072469.cos.ap-nanjing.myqcloud.com/1620465222-JBWMfJ-file_1620465222671)

此时，就有对应的公式：
$$
index=(index+m-1)\%(list.size());
$$
![真实位置计算](https://img-1312072469.cos.ap-nanjing.myqcloud.com/1620465222-sRKSCI-file_1620465222668)

使用这个公式一举几得，既能把上面m过大循环过多的情况解决，又能找到真实的位置，就是将这个环先假设成线性的然后再去找到真的位置：

![img](https://pic.leetcode-cn.com/1620465222-iQoBqQ-file_1620465222649)

```java
public int lastRemaining(int n, int m) {
        if (m == 1) {
            return n - 1;
        }
        List<Integer> res = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            res.add(i);
        }
        int index = 0;
        while (res.size() > 1) {
            index = (index + m - 1) % res.size();
            res.remove(index);
        }
        return res.get(0);
    }
```

继续考虑，这个时候我们真的需要使用容器吗，其实我们只需要对应的位置，然后返回对应得知，这个时候，上面用求余可以解决m比n大很多很多的情况(即理论上需要转很多很多圈的情况)。但是还可能存在n本身就很大的情况，无论是顺序表ArrayList还是链表LinkedList去频繁查询、删除都是很低效的。

因此，我们需要将公式进行总结，找到n和m的关系，对应的公式如下：
$$
f(n,m)=(f(n-1,m)+m)\%n
$$
f(n,m)指n个人，报第m个编号出列最终编号

我们举个例子，有0 1 2 3 4 5 6 7 8 9十个数字，假设m为3,最后结果可以先记成f(10,3)，即使我们不知道它是多少。

当进行第一次时候，找到元素2 删除，此时还剩9个元素，但起始位置已经变成元素3。等价成3 4 5 6 7 8 9 0 1这9个数字重写开始找。

![f(10,3)删除第一个数](https://pic.leetcode-cn.com/1620465222-bNINmu-file_1620465222660)

此时这个序列最终剩下的一个值即为f(10,3)，这个序列的值和f(9,3)不同，但是都是9个数且m等于3，所以其删除位置是相同的，即算法大体流程是一致的，只是各位置上的数字不一样。所以我们需要做的事情是找找这个序列上和f(9,3)值上有没有什么联系。

寻找过程中别忘记两点，首先可通过**%符号**对数字有效扩充，即我们可以将3 4 5 6 7 8 9 0 1这个序列看成(3,4,5,6,7,8,9,10,11)%10.这里的10即为此时的n数值。

另外数值如果是连续的，那么最终一个结果的话是可以找到联系的(差值为一个定制)。所以我们可以就找到f(10,3)和f(9,3)值之间结果的关系，可以看下图：

![f(10,3)删除一次和f(9,3)](https://pic.leetcode-cn.com/1620465222-EZkOOc-file_1620465222663)

所以f(10,3)的结果就可以转化为f(9,3)的表达,后面也是同理：
$$
f(10,3)=(f(9,3)+3)\%10 \\
f(9,3)=(f(8,3)+3)\%9 \\
…… \\
f(2,3)=(f(1,3)+3)\%2 \\
f(1,3)=0
$$


那么这个时候，我们可以使用递归进行实现

```java
public int iceBreakingGame(int n, int m) {
         if (n == 1) {
            return 0;
        }
        return (iceBreakingGame(n - 1, m) + m) % n;
    }
```

使用递归的时候会对其中的空间造成浪费，因此，我们可以将递归改成迭代：

```java
public int iceBreakingGame(int n, int m) {
//        if (n == 1) {
//            return 0;
//        }
//        return (iceBreakingGame(n - 1, m) + m) % n;
        int index = 0;
        for (int i = 1; i <= n; i++) {
            index = (index + m) % i;
        }
        return index;
    }
```
