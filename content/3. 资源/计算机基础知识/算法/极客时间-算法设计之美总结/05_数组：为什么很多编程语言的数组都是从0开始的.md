为了解答这个问题，首先我们得知道数组的概念。

数组（Array）是一种线性表数据结构。它用一组连续的内存空间，来存储一组具有相同类型的数据。

线性表（Linear List），顾名思义，失数据排成像一条线一样的结构。每个线性表上的数据最多只有钱和后面连个方向。除了数组，链表、队列、栈等也是线性表结构。

![img](https://static001.geekbang.org/resource/image/b6/77/b6b71ec46935130dff5c4b62cf273477.jpg?wh=1142*833)

非线性表，数据之间不是简单的前后关系。比如说二叉树、堆、图等结构。

![img](https://static001.geekbang.org/resource/image/6e/69/6ebf42641b5f98f912d36f6bf86f6569.jpg?wh=1142*727)

连续的内存空间和相同的数据。正是这两个限制，才有了一个堪称“杀手锏”的特性：“随机访问”。带来的坏处就是数组的很多操作变得非常低效，比如想在数组中删除、插入一个数据，为了保证数组的连续性，就需要做大量的数据搬移工作。

数组是如何实现根据下表随机访问数组元素的？

通过寻址进行访问，对应的公式如下：
$$
a[i]_{address} = base_{address} \times data\_type\_size
$$
其中 data_type_size 表示数组中每个元素的大小。我们举的这个例子里，数组中存储的是 int 类型数据，所以 data_type_size 就为 4 个字节。

因此，当我们回答链表与数组的不同时，对与数组的查找时间复杂度的描述，应该这么描述：数组支持随机访问，根据下表随机访问的时间复杂度为O(1)。

## 低效的“插入”和“删除”

在进行插入的时候，如果直接插入到最后一个元素中，时间复杂度就是O(1)。如果插入到第一个元素后，这个时候时间复杂度就是O(n)，由于访问每个数据的概率相同，因此对应的平均时间复杂度就是：$\frac{1 + 2 + .. + n}{n} = O(n)$。

当然，在某些特殊的场景下，我们要将元素插入到对应的第K个位置，这个时候，我们可以直接进行插入，将原本位置的元素放在后面。

![img](https://static001.geekbang.org/resource/image/3f/dc/3f70b4ad9069ec568a2caaddc231b7dc.jpg?wh=1142*511)

现在我们说删除，上面的复杂度是相同的，但是，现在我们删除连续空间的元素，我们大可删除一次。

这个就相当于我们现在攒了很多臭袜子，我们一次清洗。

JVM中的垃圾回收算法在进行回收的时候采用的就是这种策略。[[02_垃圾收集算法]]

这里回想一下JVM的垃圾回收算法：

1. 标记-清除算法。

   1. 首先标记需要进行回收的对象。
   2. 在标记完成后，统一回收掉所有被标记的对象。
   3. 也可以反过来，标记存活的对象。
   4. 统一回收标记对象

   这个里面存在的问题会产生大量的碎片空间。

2. 标记-复制算法。

   1. 将可用的内存空间划分成大小相等的两块，每次使用其中的一块。
   2. 当这一块已经使用完了，就把还存活者的对象复制到另外一块上面，然后再把对应的内存空间一次清理掉。

   这个的话会浪费一般的空间。

3. 标记-整理算法。

   1. 首先标记需要进行回收的对象。
   2. 让存活的对象移动到空间的一段，然后直接清理掉边界以外的内存。

这个过程，其实就是我们将不需要的元素进行移动，然后统一进行清理。

## 警惕数组越界

```c
int main(int argc, char* argv[]){
    int i = 0;
    int arr[3] = {0};
    for(; i<=3; i++){
        arr[i] = 0;
        printf("hello world\n");
    }
    return 0;
}
```

c语言中不存在对应的数组越界提醒，因此，在进行运行的时候，可能存在死循环，及对应a[3]与i指向同一个地方。

访问数组的本质就是访问一段连续内存，只要数组通过偏移计算得到的内存地址是可用的，那么程序就可能不会报任何错误。

因此，在进行编写的时候，应该注意上述错误。

## 容器是否能够完全替换数组

ArrayList容器最大的优势就是可以将很多数组操作的细节封装起来。比如前面提到的数组插入、删除数据时需要搬移其他数据等。另外，它还有一个优势，就是支持动态扩容。

动态扩容的时候，加载因子是0.75，当使用空间为长度 * 加载因子的时候，进行扩容，扩容空间为原数组长度的1.5倍。

1. Java ArrayList 无法存储基本类型，比如 int、long，需要封装为 Integer、Long 类，而 Autoboxing、Unboxing 则有一定的性能消耗，所以如果特别关注性能，或者希望使用基本类型，就可以选用数组。
2. 如果数据大小事先已知，并且对数据的操作非常简单，用不到 ArrayList 提供的大部分方法，也可以直接使用数组。

对于业务开发，直接使用容器就足够了，省时省力。毕竟损耗一丢丢性能，完全不会影响到系统整体的性能。但如果你是做一些非常底层的开发，比如开发网络框架，性能的优化需要做到极致，这个时候数组就会优于容器，成为首选。

## 开头问题

为什么是从零开始的。

其实，在对应寻址公式上面已经进行了回答。
$$
a[k]_{address} = base_{address} + k \times type\_size
$$

如果说不是从零开始，那么，每次都需要多计算一次对应减法操作。

当然可能是历史原因，C 语言设计者用 0 开始计数数组下标，之后的 Java、JavaScript 等高级语言都效仿了 C 语言，或者说，为了在一定程度上减少 C 语言程序员学习 Java 的学习成本，因此继续沿用了从 0 开始计数的习惯。实际上，很多语言中数组也并不是从 0 开始计数的，比如 Matlab。甚至还有一些语言支持负数下标，比如 Python。

## 总结

数组用一块连续的内存空间，来存储相同类型的一组数据，最大的特点就是支持随机访问，但插入、删除操作也因此变得比较低效，平均情况时间复杂度为 O(n)。
